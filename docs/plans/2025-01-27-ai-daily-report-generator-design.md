## 1. 产品概述

### 1.1 产品定位
面向解决方案架构师的**访谈式 AI 日报生成器**，通过全双工实时语音对话（类似打电话）收集每日工作内容，自动生成结构化日报。

### 1.2 核心价值
- **语音优先**：随时随地，长按说话，像打电话一样自然
- **智能引导**：AI 主动提问，深度挖掘工作细节和价值点
- **自动整理**：提取关键信息，生成专业日报，强调技术决策和商业价值

### 1.3 目标用户
- **主要用户**：管理 5-10 个项目的解决方案架构师
- **使用场景**：通勤路上、会议间隙、随时记录
- **汇报对象**：向上级汇报项目进度，强调商业价值和技术成果

## 2. 核心功能

### 2.1 语音交互模式
**全双工实时对话**：
- 用户可以随时打断 AI，AI 可以随时插话
- 延迟 <500ms，提供流畅的对话体验
- 支持中途切换项目，灵活调整对话流程

**引导式访谈**：
- AI 主动提问，逐步深入探索
- 混合模式：AI 根据用户回答灵活调整顺序
- �盖项目维度：今日工作 + 明日计划

### 2.2 智能整理能力
**自动提取与分类**：
- 任务类型识别：开发/会议/沟通/学习/风险管理
- 关键词提取：技术栈、团队协作、风险点、依赖关系
- 结构化存储：JSON 格式存储

**高级智能功能**：
- 任务优先级排序
- 重复内容去重
- 趋势分析：对比历史日报
- 风险预警：识别潜在问题和阻塞

### 2.3 日报输出
**自定义结构**：今日工作 + 明日计划
- 支持多项目汇总
- 强调技术决策和商业价值
- 可导出为 Markdown、PDF、邮件

## 3. 技术架构

### 3.1 整体架构
前后端分离的移动端 Web 应用，支持全双工实时语音对话。

**前端层**：
- React 18 + Vite
- PWA 支持离线访问
- WebRTC API 实时音频采集和播放
- Tailwind CSS 移动端响应式设计

**信令服务器**：
- Node.js + WebSocket (Socket.io)
- WebRTC 信令交换（SDP offer/answer）
- ICE 候选收集和 NAT 穿透

**媒体处理层**：
- Node.js + 豆包 API
- 实时语音识别（ASR）
- 对话生成（LLM）
- 流式语音合成（TTS）

**数据层**：
- PostgreSQL（对话历史和日报）
- Redis（会话状态和缓存）

### 3.2 豆包 API 集成

**第一阶段 - 语音识别（ASR）**：
- 实时音频流：16kHz 采样率
- 分段处理：每 500ms 调用豆包实时语音识别 API
- 流式返回：实时返回识别结果
- 停顿检测：1.5 秒静音判断为说话结束

**第二阶段 - 对话生成（LLM）**：
- 上下文管理：维护完整对话历史
- 实时推理：豆包大模型 API
- 流式输出：打字机效果

**第三阶段 - 语音合成（TTS）**：
- 流式合成：实时生成音频流
- 边说边播：队列机制
- 打断处理：用户说话时停止播放

**全双工控制**：
- VAD（语音活动检测）实时监控
- 用户说话 → 暂停 AI 输出
- 用户停顿 300ms → AI 继续

### 3.3 全双工交互流程

**启动**：
- 用户打开网页 → 点击"开始通话"
- 建立 WebRTC 连接
- AI 播放开场白："您好，我是日报助手，今天想从哪个项目开始？"

**对话进行**：
- **用户说话时**：发送音频到豆包 ASR → 显示实时文字 → AI 聆听模式
- **用户停顿时**：800ms 静音 → ASR 返回完整句子 → LLM 生成回复 → TTS 播放
- **打断机制**：用户说话 → 停止 TTS → 切换到聆听模式

**智能引导**：
- 完成项目 A 今日工作回顾 → 自动询问项目 A 明日计划
- 用户可以："先说说项目 B" → AI 理解并切换话题

**总结**：
- 检测访谈充分（5-8 轮对话）
- 询问："我已经整理好了今天的日报，需要我为您总结一下吗？"
- 用户确认 → 播报结构化日报 → 自动保存

## 10. 风险与缓解

### 10.1 技术风险
**风险**：WebRTC 兼容性问题
**缓解**：使用 adapter.js，充分测试 iOS Safari

**风险**：实时音频延迟
**缓解**：优化音频分片大小，使用 UDP

### 10.2 产品风险
**风险**：用户不愿意对着手机说话
**缓解**：提供文字输入备选方案

**风险**：AI 引导不够智能
**缓解**：持续优化对话引擎
